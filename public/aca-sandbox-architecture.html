Dev user and Prod user are browser entry points on the same laptop. Local development defaults to PGlite; the dashed database route is opt-in. Workbench PostgreSQL stores domain data; Controller PostgreSQL stores lifecycle coordination only. No Agent runs locally, and neither database stores Agent transcripts or sandbox files. Both Workbench servers are replaceable. In the proposed target, the controller owns lifecycle and selects the sandbox that each server reaches directly for runtime RPC.

1. Why a separate sandbox control plane

Sandbox lifecycle is durable infrastructure coordination. It should not live inside the replaceable Workbench application process.

The controller stores infrastructure coordination only: locators, operation identities, fences, receipts and cleanup work. Agent transcripts, prompts, credentials and repository data remain outside it.

2. Runtime operations

Replace repeated ACA exec calls with an authenticated RPC channel hosted by the sandbox runtime.

#572 is the first data-plane slice of this model: it adds authenticated storage-control RPC to the existing sandbox runtime bridge. “Direct” describes only the runtime data path: the controller first allocates, fences and authorizes the sandbox, while Workbench then sends runtime traffic to that exact sandbox without turning the controller into a transcript or storage proxy.

3. Secret delivery

Stop staging credentials as files that must later be removed through the same unreliable exec path.

The credential-bootstrap work keeps the capability, nonce and locator out of command text, URLs, files and diagnostics. ACA injects them only on the exact approved outbound request; the launcher then passes credentials directly to the intended child process.
